# TeachQRS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a teacher-owned classroom Quick Response System: required student numbers, reusable question sets across subclasses, CSV/Excel question import-export, and CSV response export.

**Architecture:** FastAPI serves teacher admin, projector live view, and student phone pages. SQLite (WAL) stores sets, subclasses, sessions, participants, and responses. Tiny JS polls live state. Domain logic lives in plain Python modules so pytest can cover identity, import, and export without a browser.

**Tech Stack:** Python 3.11+, FastAPI, Jinja2, python-multipart, bcrypt, itsdangerous, qrcode, openpyxl, pytest, uvicorn.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-09-05-teachqrs-design.md`
- Student number: trimmed, 3–20 chars, `A-Za-z0-9_-` only; required before any question payload
- Question CSV header exactly: `question_number,prompt,type,choice_a,choice_b,choice_c,choice_d,choice_e,correct,points`
- Response CSV header exactly: `session_name,join_code,subclass,student_number,question_number,prompt,type,response,correct_answer,is_correct,round,submitted_at,updated_at`
- Bind `0.0.0.0`; join URLs use request host, not localhost, when a non-loopback host is present
- UI: ink `#1b2430`, paper `#f6f1e8`, live coral `#d64545`, go green `#2f6f4e`
- No SSO, lucky draw, LTI, or multi-teacher accounts
